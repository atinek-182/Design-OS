# Project Location & Organization Rule

## Mandatory Project Destination
Whenever creating a new website, web application, landing page, UI prototype, or project:
- **ALWAYS** initialize/build it inside the `projects/` directory (`d:\Design-OS\projects\` -> `D:\projects\`).
- **NEVER** create new project codebases in the root of `Design-OS` or temporary directories unless explicitly instructed.

## Subfolder Categorization Hierarchy
Place the new project in the most relevant subfolder under `projects/`:

- **`projects/Websites/<project-name>`**: Websites, marketing sites, landing pages, agency/client sites, portfolios.
- **`projects/Products/<project-name>`**: Full web apps, SaaS products, platforms, dashboards.
- **`projects/Sandbox/<project-name>`**: Quick spikes, throwaway mockups, experimental UI sandbox files.
- **`projects/For design/<project-name>`**: UI kits, design system explorations, design tool extensions.
- **`projects/For AIOS/<project-name>`**: AI OS, subagent harnesses, and AI tool integrations.
- **`projects/Learning/<project-name>`**: Demos, tutorials, and learning sandboxes.
- **`projects/Brand/<project-name>`**: Brand web properties and assets.
- **`projects/My advisors/<project-name>`**: Advisory and consultancy projects.

*If no specific category is mentioned, default to `projects/Websites/<project-name>` for websites/landing pages or `projects/Products/<project-name>` for web apps.*
